# Research store contract

All machine records are UTF-8. Preserve the V3 research ledger schema. Add narrative_plan.json and editorial_review.json in V3.1; rendering adds report_citations.json and report_quality.json. The audit ZIP keeps all records plus research_audit.txt, audit_stats.json and literature_map.csv. No audit appendix or Markdown report is injected into the review DOCX.

Paper: id, title, authors, year, venue, volume, pages or article_number, verified DOI if present, other identifiers, record_type (paper, review, preprint, thesis, or web), version_group when justified, role, screening_state, topics, methods, system, platform, contribution, limitations, relevance_reason, anchor_score/components, discovery_paths, first_seen_round, role_assigned_round, access_status, reading_priority, identity_checked, and public provenance URLs. Optional authors_acs and journal_abbreviation must be verified metadata, not guesses. DOI format validation does not verify existence. Keep incomplete candidates with an explicit temporary id rather than discarding them for missing author/year.

Query ledger event: event_id, query_id, timestamp, round, family, route, source, query, status (COMPLETED, PARTIAL, FAILED, UNAVAILABLE, NOT_APPLICABLE), observed_returned_count, candidate_ids, error and parameters. A record may appear under many query IDs. Each query ID should denote one search attempt or retried attempt; record tool-returned results, not purported engine-wide hits. Source failures appear in failure_diagnostics.json too.

Source: source_id, paper_id, url, title, accessed_date (YYYY-MM-DD), access_level (FULLTEXT, PARTIAL, ABSTRACT, METADATA, UNAVAILABLE), read_state (READ, NOT_READ, FAILED), retrieval_surface (HOST_OPEN_PAGE or HOST_SEARCH_RESULT), tool_result_ref for a read indexed result, abstract_complete true only when the whole indexed abstract is visible, version_note, source_kind (primary, review, repository, publisher, secondary). Record a page-opening failure in the ledger or failure diagnostics even when its indexed abstract remains usable. Scientific importance is a separate paper field.

Evidence: evidence_id, paper_id, source_id, locator, paraphrase, evidence_level matching the actually read source, direction (support, contradict, context), conditions, comparator, limits, and optional measured values. Store concise original-language excerpts only within copyright bounds; paraphrase by default.

Claim: claim_id, text, claim_type (summary, detailed, figure_table, metadata, hypothesis), standing (supported, contradicted, mixed, uncertain), evidence_ids, limitations, is_inference. Detailed or figure/table interpretation requires a relevant read FULLTEXT evidence object. Summary claims may draw on actually read abstracts if limited to information explicitly present.

Coverage row: subquestion, terminology, route coverage, relevant/core paper IDs, recent-work status, direct primary evidence, gap_severity (none, low, important), gap text, next query. Anchor audit row: subquestion, route (backward, forward, related, review, exact_method, competing), status, candidate IDs, rationale, replacement ID. Reading queue rows are paper ID, priority (Must Read, Should Read, Optional), and why.

Round record: round, query_ids, new_concepts, new_contradictions, new_terms, commentary. The CLI derives new candidates and new Core IDs from the ledger and paper records. Meaningful discoveries must be logged in the round when observed. Replaying identical query/route/source combinations in a later round does not qualify as independent low-novelty evidence.

Report draft: format_version="3.1", title, as_of_date, length_profile (full, user_concise, user_custom, evidence_limited), length_reason when not full, tldr, sections, limitations and actual execution_mode. Use assets/report-draft-template.json as a blank scaffold. The author supplies scientific Chinese prose; the renderer cannot write conclusions. A V3 summary/flat-block draft is rejected with a rewrite instruction; paper/evidence data remain reusable.

TL;DR: exactly five paragraph objects with ordered role object, state, advances, limits, reader_takeaway. Sections: introduction, overview, 1-4 theme chapters, limitations, conclusion, in order. Introduction and conclusion have blocks of continuous paragraphs. Intro roles cover object_value, principles_history, development_status, bottleneck, scope_roadmap; conclusion roles cover field_state, scientific_synthesis, key_unresolved, grounded_outlook. A paragraph's roles array can combine functions naturally.

Each body chapter has title without manual numbering, opening paragraph, 2-4 subsections and closing paragraph. Each subsection has title and substantive blocks; begin with a synthesis paragraph. Blocks are paragraph or table, with no extra heading blocks. A paragraph either has text/claim_ids or spans=[{text,claim_ids,content_kind?}]. Use spans for distinct factual claims so references appear beside the supported sentence. content_kind="scientific" is the default and requires evidence-backed claim IDs; method/scope text may omit IDs. A table has caption, columns, optional positive column_weights, and rows with cells/claim_ids. Every factual row needs supporting claims.

Material limitations are exact snippets from the visible introduction/limitations prose. Keep them in limitations too so the gate can detect a boundary that exists only in metadata. Record hypotheses as inference in the claims and prose. Never type numbered references into a draft; the renderer derives them from claim/evidence IDs.

Narrative plan: main_storyline, core_tension, chapter_questions (one per body chapter), overall_insights (3-5), and useful chapter_opening_judgments, representative_papers, supporting/conflicting_evidence. Do not display this planning artifact in the review. Editorial review: format_version and items keyed by the 19 REVIEW_KEYS in scripts/report_contract.py. Each item has status PASS/LIMITED, a specific basis, and optional locations. Correct FAIL/PENDING before delivery. LIMITED needs a material visible limitation.

Checkpoint: question, current phase, round, completed routes, current corpus, coverage gaps, anchor state, source failures, next action, and status. On limitation, mark COMPLETED_WITH_LIMITATIONS and report rather than stall.

The CSV literature map includes a paper row per distinct work or justified version, its map and access fields, and path counts. A unique-paper count differs from a work-group count when linked preprints/publications exist. Provenance/event counts retain duplicates, with explicit denominators.
